# Backend (.NET 10)

Aplica a **ambas** APIs (`backend/auth/` y `backend/business/`). Lo específico de
autenticación está en [`auth.md`](auth.md). La estructura de capas y la regla de
dependencias están en [`arquitectura.md`](arquitectura.md).

## Estructura de una solución

## Configuración común (`Directory.Build.props`)

- `<Nullable>enable</Nullable>`, `<ImplicitUsings>enable</ImplicitUsings>`
- `<TreatWarningsAsErrors>true</TreatWarningsAsErrors>`
- `<LangVersion>latest</LangVersion>`
- Analizadores: `Microsoft.CodeAnalysis.NetAnalyzers` (ya incluido), `AnalysisLevel`
  = `latest-recommended`.
- `.editorconfig` con estilo consistente (indentación, `var` cuando el tipo es
  evidente, `file-scoped namespaces`, orden de `using`).

## EF Core

- **`DbContext` vive en `Infrastructure`** (`BusinessDbContext`). `Domain` y
  `Application` nunca lo referencian; usan puertos (`IOrderRepository`,
  `IUnitOfWork`).
- **Una configuración por entidad**: `IEntityTypeConfiguration<T>` en
  `Persistence/Configurations/`. Nada de data annotations en las entidades de dominio.
- **Mapeo al esquema existente** `requirements/restaurant_schema.sql`:
  - Nombres de tabla y columna en **snake_case** (`table_sessions`, `opened_at`).
    Usar un convertidor de nombres o mapear explícitamente en cada configuración.
  - PKs `integer GENERATED BY DEFAULT AS IDENTITY` →
    `ValueGeneratedOnAdd()` con `UseIdentityByDefaultColumn()`.
  - Reproducir en el modelo los `CHECK`, `UNIQUE` y el **índice único parcial**
    `ux_table_sessions_one_open_per_table ON (table_id) WHERE closed_at IS NULL`
    (`HasIndex(...).HasFilter("closed_at IS NULL").IsUnique()`).
  - Los campos de estado (`orders.status`, `orders.channel`, `operational_status`,
    `movement_type`, …) son `varchar` en la BD. En el modelo se mapean a **enums de
    aplicación** con conversión a string, o a constantes. El **catálogo completo de
    valores se consulta al usuario** antes de fijarlo (spec deja varios abiertos:
    `MET-01`, §14).
- **Migraciones**: viven en `Infrastructure/Persistence/Migrations`, versionadas en
  el repo. Se generan y aplican **dentro del contenedor** (ver [`docker.md`](docker.md)):

  ```bash
  docker compose run --rm backend-business dotnet ef migrations add <Nombre> \
    --project src/RestoManager.Business.Infrastructure \
    --startup-project src/RestoManager.Business.Api
  docker compose run --rm backend-business dotnet ef database update \
    --project src/RestoManager.Business.Infrastructure \
    --startup-project src/RestoManager.Business.Api
  ```

  Revisa siempre el SQL generado (`dotnet ef migrations script`) contra
  `restaurant_schema.sql`: **no debe divergir** del esquema acordado sin que sea un
  cambio consultado.
- **Sin lógica en la BD**: no se crean triggers ni funciones. La coherencia la
  garantiza `Application` (spec §9).
- **`DateTime` siempre UTC**; columnas `timestamp` → `timestamp with time zone` con
  `Npgsql` configurado para UTC.

## Casos de uso (Application)

- **Un handler por operación de negocio**. Entrada: `Command`/`Query` (record).
  Salida: un `Result` explícito (éxito con datos, o error de dominio tipado). Evita
  lanzar excepciones para flujos esperables; reserva excepciones para invariantes
  rotos.
- El handler es quien **abre la transacción** (`IUnitOfWork`/`DbContext` transaction)
  cuando toca varias tablas — obligatorio para inventario (`INV-05`), pagos, y
  cualquier operación multi-registro (spec §1.1).
- **Validación de entrada** con **FluentValidation** (`<Caso>Validator`), enganchada
  como comportamiento antes del handler. La validación *de negocio* que necesita
  datos de la BD va dentro del handler, no en el validator.
- Los handlers verifican los **invariantes de dominio aplicables**
  (`DOM-01…DOM-10`, ver [`arquitectura.md`](arquitectura.md)) antes de persistir.
- **Sin MediatR obligatorio**: se puede invocar el handler directamente desde el
  endpoint. Si se introduce un dispatcher, se consulta primero (dependencia nueva).

## Capa Api

- **Minimal API** por módulo (`Endpoints/<Modulo>Endpoints.cs`) o Controllers —
  elegir uno y ser consistente; por defecto, minimal API.
- **DTOs propios** en `Contracts/`. Nunca se serializan entidades de `Domain`.
- **Errores** en formato `ProblemDetails` (RFC 7807). Mapa único
  error de dominio → status code en un middleware/handler.
- **Paginación** consistente: `?page=&pageSize=` con respuesta
  `{ items, page, pageSize, total }`. `pageSize` con tope.
- **Versionado** de API por URL (`/api/v1/...`).
- **OpenAPI** habilitado (`Microsoft.AspNetCore.OpenApi`) + UI de Swagger en
  desarrollo.
- `async`/`await` **de extremo a extremo**; nada de `.Result`/`.Wait()`.
- Health checks (`/health`) para los contenedores.
- Logging estructurado (`ILogger<T>`); sin `Console.WriteLine`.

## Testing

| Nivel | Proyecto | Qué cubre | Infra |
|---|---|---|---|
| Unit | `*.Domain.Tests` | Reglas invariantes de entidades/value objects | Ninguna |
| Unit | `*.Application.Tests` | Handlers con puertos en doble de prueba (fakes/mocks) | Ninguna |
| Integración | `*.Api.IntegrationTests` | Endpoint → EF Core → Postgres real | **Testcontainers** (`postgres:17`) o servicio compose de test |

- Framework: **xUnit** + `FluentAssertions`. Dobles: `NSubstitute`.
- Los tests de integración levantan su propia BD efímera; no dependen de datos
  previos.
- Todo cambio de comportamiento llega con test. `dotnet test` debe quedar verde
  dentro del contenedor.

## Buenas prácticas .NET (checklist rápido)

- [ ] Nullable habilitado y sin warnings.
- [ ] Inyección de dependencias por **constructor**; nada de `service locator`.
- [ ] Entidades de dominio con invariantes protegidos (constructores/fact? métodos,
      setters privados); no anemia total si la regla es del agregado.
- [ ] `record` para DTOs, commands y value objects inmutables.
- [ ] `IClock`/`TimeProvider` en vez de `DateTime.UtcNow` directo (testabilidad).
- [ ] Configuración vía `IOptions<T>` tipado, valores desde `appsettings` + env vars.
- [ ] Secretos (connection strings, claves) por variables de entorno / `.env`,
      nunca en `appsettings` del repo.
- [ ] `CancellationToken` propagado hasta EF Core.
